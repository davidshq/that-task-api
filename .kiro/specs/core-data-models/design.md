# Design Document

## Overview

This design implements the core data models for That Task API using Supabase's PostgreSQL database with auto-generated REST APIs. The architecture leverages PostgreSQL's advanced features for hierarchical data, JSONB for flexible custom fields, and Row Level Security for fine-grained permissions.

## Architecture

### Database-First Approach
- PostgreSQL schema defines the data model
- PostgREST auto-generates REST APIs from schema
- Row Level Security (RLS) policies enforce permissions
- Database triggers handle audit logging and timestamps
- JSONB columns provide flexibility for custom fields

### Hierarchical Data Model
The "everything-as-a-list" approach uses a polymorphic structure where both Lists and Tasks can have parent-child relationships, enabling flexible organizational hierarchies.

## Components and Interfaces

### Database Schema

#### Users Table (auth.users extended)
```sql
-- Extends Supabase auth.users with profile information
CREATE TABLE public.user_profiles (
  id UUID REFERENCES auth.users(id) PRIMARY KEY,
  display_name TEXT,
  avatar_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### Lists Table
```sql
CREATE TABLE public.lists (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  parent_id UUID REFERENCES public.lists(id),
  owner_id UUID REFERENCES auth.users(id) NOT NULL,
  type TEXT DEFAULT 'list' CHECK (type IN ('list', 'project', 'workspace', 'folder')),
  custom_fields JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### Tasks Table
```sql
CREATE TABLE public.tasks (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  parent_id UUID REFERENCES public.tasks(id),
  list_id UUID REFERENCES public.lists(id),
  owner_id UUID REFERENCES auth.users(id) NOT NULL,
  assigned_to UUID REFERENCES auth.users(id),
  status TEXT DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done', 'cancelled')),
  priority TEXT DEFAULT 'medium' CHECK (priority IN ('low', 'medium', 'high', 'urgent')),
  due_date TIMESTAMPTZ,
  tags TEXT[] DEFAULT '{}',
  custom_fields JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### Custom Field Definitions Table
```sql
CREATE TABLE public.custom_field_definitions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT NOT NULL,
  field_type TEXT NOT NULL CHECK (field_type IN ('text', 'number', 'date', 'boolean', 'select')),
  entity_type TEXT NOT NULL CHECK (entity_type IN ('task', 'list')),
  options JSONB, -- For select fields
  required BOOLEAN DEFAULT FALSE,
  owner_id UUID REFERENCES auth.users(id) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

#### Audit Log Table
```sql
CREATE TABLE public.audit_logs (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  entity_type TEXT NOT NULL,
  entity_id UUID NOT NULL,
  action TEXT NOT NULL CHECK (action IN ('create', 'update', 'delete')),
  old_values JSONB,
  new_values JSONB,
  user_id UUID REFERENCES auth.users(id),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### API Endpoints (Auto-generated by PostgREST)

#### Lists API
- `GET /lists` - List all accessible lists
- `POST /lists` - Create new list
- `GET /lists?id=eq.{id}` - Get specific list
- `PATCH /lists?id=eq.{id}` - Update list
- `DELETE /lists?id=eq.{id}` - Delete list
- `GET /lists?parent_id=is.null` - Get root lists
- `GET /lists?parent_id=eq.{id}` - Get child lists

#### Tasks API
- `GET /tasks` - List all accessible tasks
- `POST /tasks` - Create new task
- `GET /tasks?id=eq.{id}` - Get specific task
- `PATCH /tasks?id=eq.{id}` - Update task
- `DELETE /tasks?id=eq.{id}` - Delete task
- `GET /tasks?list_id=eq.{id}` - Get tasks in list
- `GET /tasks?parent_id=eq.{id}` - Get subtasks

### Database Functions

#### Hierarchical Queries
```sql
-- Function to get full hierarchy path
CREATE OR REPLACE FUNCTION get_list_path(list_uuid UUID)
RETURNS TEXT[] AS $$
WITH RECURSIVE path AS (
  SELECT id, title, parent_id, ARRAY[title] as path
  FROM lists WHERE id = list_uuid
  UNION ALL
  SELECT l.id, l.title, l.parent_id, l.title || p.path
  FROM lists l JOIN path p ON l.id = p.parent_id
)
SELECT path FROM path WHERE parent_id IS NULL;
$$ LANGUAGE SQL;
```

## Error Handling

### Database Constraints
- Foreign key constraints ensure referential integrity
- Check constraints validate enum values
- NOT NULL constraints prevent missing required data
- Unique constraints prevent duplicates where needed

### RLS Policy Errors
- 403 Forbidden for unauthorized access attempts
- Policies return empty results for inaccessible data
- Clear error messages for policy violations

## Security Considerations

### Row Level Security Policies
```sql
-- Users can only access their own profile
CREATE POLICY "Users can view own profile" ON user_profiles
  FOR SELECT USING (auth.uid() = id);

-- Users can access lists they own or are shared with
CREATE POLICY "Users can access owned lists" ON lists
  FOR ALL USING (auth.uid() = owner_id);

-- Users can access tasks in accessible lists
CREATE POLICY "Users can access tasks in owned lists" ON tasks
  FOR ALL USING (
    auth.uid() = owner_id OR 
    EXISTS (SELECT 1 FROM lists WHERE lists.id = tasks.list_id AND lists.owner_id = auth.uid())
  );
```
